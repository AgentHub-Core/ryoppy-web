## 0. Executive Summary

**りょっぴー**は、旅行中にその土地を築いた富豪・権力者・実業家などの歴史人物と出会い、短い物語を聞いて収集しながら、街の歴史的な因果関係を解き明かしていく位置情報連動型の歴史図鑑ゲームである。

ユーザーは専用ツアーへ参加する必要がない。通常どおり観光し、アプリを開いたときに周辺の未発見人物を確認する。人物に関係する地点へ近づくとデフォルメされたキャラクターが出現し、ユーザーがタップして短い導入を読む、または聞くと図鑑へ登録される。

V1はCincinnatiのStreetcar沿線を対象とし、10〜12人の主要人物と20〜25か所のスポットを収録する。自分と友人のiPhoneへTestFlightで配布し、現地で一連の体験が成立する状態を完成とする。App Storeでの一般公開はV1の範囲から外す。

画面は**1950年代アメリカン・ポップ**で統一する。クリーム、コーラル、ティール、ミント、マスタードを中心に、丸いカード、太い輪郭、スターバースト、レトロ広告風の見出しを使う。デートや家族旅行で一台を一緒に見て、会話が生まれる軽い体験を優先する。

人物画面には、**推定資産の現代ドル換算、資産戦闘力、ランク、富の内訳グラフ、資産推移グラフ**を表示する。Alphaの金額はUI検証用の仮推定値として扱い、公開版へ進む前に再調査する。

# Specification

## 1. Objective

旅行先の名所を「見た」で終わらせず、その土地を形成した人物の野心、富、権力、成功、対立、失敗、負の遺産まで短く面白く理解できる体験を作る。

達成したいことは以下。

1. 旅行中の行動を大きく変えずに、その土地の背景を知れる
2. 歴史に詳しくない人でも、人間ドラマとして楽しめる
3. 現地訪問によって人物図鑑が埋まり、収集する楽しさが生まれる
4. 人物・場所・事件の関係を追うことで、街が形成された因果関係が見える
5. 写真と歴史人物を結びつけ、旅行後にも記憶を振り返れる

---

## 2. Background

一般的な旅行では、建物、記念碑、旧邸宅などを見ても、その場所がなぜ存在するのか、誰が富を築き、誰と争い、何を街へ残したのかまでは分かりにくい。

既存の音声ガイドや観光アプリは、決められたツアーを順番に回る形式や、場所を起点に説明する形式が多い。りょっぴーは、**人物を収集対象かつ物語の入口**にし、通常の旅行へ自然に同行する。

中心となる歴史の切り口は、以下。

- 金
- 権力
- 事業
- 成功
- 野心
- 家系
- ライバル
- スキャンダル
- 社会的影響
- 成功の代償
- 現代まで残る遺産

## 3. Target User

### 3.1 Primary User

20〜40代を中心とした個人旅行者。

### 3.2 User Characteristics

- 名所を見るだけでは物足りない
- 歴史の専門家と異なる
- 旅行中にスマートフォンで短く背景を知りたい
- 年表より人物の野心、成功、対立、失敗に興味がある
- 長時間のガイドツアーには参加しない
- 発見、収集、アンロックに楽しさを感じる
- デートや家族旅行でも、1台の画面や音声を一緒に楽しみたい
- 旅行中に相手と話せる軽い小ネタを求める
- 金額、ランキング、グラフで人物の規模を直感的に知りたい

### 3.3 V1 Usage Model

V1のアプリ操作は1人用として設計する。ただし、スマートフォン1台をデート相手や家族と共有して使えるよう、音声と全文テキストの両方を提供する。

リアルタイム同期、QR参加、投票、共同旅行記などの正式なグループ機能はV1に含めない。

### 3.4 Non-Primary Users

V1では以下を主対象にしない。

- 学術的な網羅性を求める研究者
- 歴史マニア向けの専門データベース利用者
- 学校教育を主用途とする子ども・教師
- 自治体、観光局、博物館などの法人利用者

## 6. User Flow

### 6.1 First Launch

1. ユーザーがアプリを起動する
2. りょっぴーの目的を短く説明する
3. 位置情報が必要な理由を説明する
4. 「アプリの使用中のみ」位置情報を要求する
5. 位置情報を許可しなくても、図鑑とサンプル人物は閲覧できる
6. Cincinnatiパックの初期データを読み込む
7. ホーム画面へ移動する

### 6.2 Discovery Flow

1. ホーム画面に現在のエリア名を表示する
2. 最も近い未発見人物を大きなカードで表示する
3. 周辺の未発見人物数、距離、おおまかな方向を表示する
4. 補助的な小型地図を表示する
5. 必要に応じて全体マップを開ける
6. 対象地点へ近づくと人物カードが反応し、遭遇可能状態になる

### 6.3 Encounter and Unlock Flow

1. ユーザーが遭遇可能な人物をタップする
2. デフォルメされた人物が一人称で登場する
3. 60〜90秒程度の導入を音声または全文テキストで体験する
4. 導入完了後、人物を図鑑へ登録する
5. 選択可能な追加質問を表示する
6. ユーザーが質問を選択する
7. 事前制作された回答を音声またはテキストで表示する
8. 質問選択肢を人物の台詞の直下に表示する
9. 選んだ回答を同じ人物画面内へ表示する
10. 推定資産の現代ドル、戦闘力、富の内訳、資産推移を確認する
11. 関連する場所、事件、企業、産業、人物を関係ノードとして解放する
12. 任意で写真を撮影または選択する
13. 写真を人物と訪問記録へ紐づける
14. ホーム画面または図鑑へ戻る

### 6.4 Purchase Flow

1. 無料対象の3人までは通常どおりアンロックできる
2. 有料対象人物へ接近した場合、人物のシルエットと短い予告を表示する
3. Cincinnati完全版の買い切り画面を表示する
4. 表示価格は$6.99
5. TestFlightではStoreKitのsandbox購入を実行する
6. 購入成功後、残り人物と完全版図鑑を解放する
7. 購入復元を利用できるようにする

### 6.5 Revisit Flow

1. アンロック済み人物の地点へ再訪する
2. 人物は重複登録されない
3. 人物カード、質問、関係ノードを再閲覧できる
4. 写真を追加できる
5. 訪問回数を内部記録してもよいが、V1ではゲーム報酬に使わない

## 7. Functional Requirements

### Discovery and Map

**FR-001**  
アプリは、ユーザーの現在地に基づき、Cincinnati Streetcar沿線の周辺人物を表示しなければならない。

**FR-002**  
ホーム画面は人物カードを主表示とし、地図を補助表示としなければならない。

**FR-003**  
ホーム画面は、最寄りの未発見人物、距離、おおまかな方向、周辺の未発見人数を表示しなければならない。

**FR-004**  
全体マップでは、未発見人物、遭遇可能人物、アンロック済み人物を異なる表示で区別しなければならない。

**FR-005**  
未発見人物の正確な情報は隠し、シルエットまたは「？」で表示しなければならない。

### Location and Check-In

**FR-006**  
位置情報は、アプリが前面で使用されている間だけ取得しなければならない。

**FR-007**  
バックグラウンド位置監視を実装してはならない。

**FR-008**  
通常はGPSを使用して遭遇可能判定を行わなければならない。

**FR-009**  
GPS精度が低い、または取得できない場合、手動チェックインを提供しなければならない。

**FR-010**  
建物への入場、営業時間、チケット購入をアンロック条件にしてはならない。

### Character Encounter

**FR-011**  
対象地点へ近づいた場合、歴史人物を遭遇可能状態として表示しなければならない。

**FR-012**  
人物は、ユーザーがタップして導入を体験するまで図鑑へ登録されてはならない。

**FR-013**  
人物はデフォルメされた2Dキャラクターとして表示しなければならない。

**FR-014**  
人物の導入は一人称で表現しなければならない。

**FR-015**  
導入は音声と全文テキストの両方で提供しなければならない。

**FR-016**

### Questions and Answers

人物アンロック後、ユーザーが選べる追加質問を表示しなければならない。

**FR-019**

### Encyclopedia

## 8. Business Rules

**BR-001 — Core Theme**  
人物と物語の選定は、金、権力、事業、成功を中心にする。

**BR-002 — Historical Balance**  
富豪や権力者を一方的に賛美せず、成功方法、社会的影響、対立、被害、負の遺産も扱う。

**BR-003 — Person-First Collection**  
人物を図鑑の主収集対象とし、場所や事件は人物関係を理解するノードとする。

**BR-004 — Encounter Condition**  
位置判定だけではアンロックしない。人物を開き、短い導入を完了した時点でアンロックする。

**BR-005 — No Mandatory Quiz**  
クイズ、写真撮影、施設入場、ルート完走をアンロック必須条件にしない。

**BR-006 — No Runtime AI in V1**  
コンテンツ制作時にはAIを使用するが、アプリ利用時の回答生成にはAIを使用しない。

**BR-007 — AI Content Production**  
人物紹介、質問、回答は、指定した資料を参照してAIが制作する。リリースするCincinnatiパックでは、その出力を固定コンテンツとして保存する。

**BR-008 — Content Confidence**  
根拠を取得できない具体的事実、台詞、逸話を事実として提示しない。

**BR-009 — Fact Classification**  
必要に応じて「確認された史実」「伝承」「演出」を区別して表示する。

**BR-010 — Free Limit**  
無料利用者がアンロックできる人物は3人とする。

**BR-011 — Purchase Unit**  
購入単位はCincinnati完全版パックとする。人物単体販売を行わない。

**BR-012 — Purchase Price Hypothesis**  
完全版の検証価格は$6.99とする。

**BR-013 — Foreground Location Only**  
V1ではバックグラウンド位置情報を取得しない。

**BR-014 — Reliability over Anti-Cheat**  
金銭的報酬やランキングがないため、厳格な不正防止より、現地利用者がGPS誤差で失敗しないことを優先する。

**BR-015 — Offline First**  
主要体験は通信状態に依存させない。

**BR-016 — Local-Only Photos**  
写真と旅行記録は端末内だけに保存する。

**BR-017 — Idempotency**  
同じ人物を複数回アンロックしても、図鑑内に重複レコードを作成しない。


**BR-018 — Modern-Dollar Primary Display**  
資産の主表示は2026年ドル換算とする。

**BR-019 — Battle-Power Scale**  
資産戦闘力は0〜10,000の相対スコアとし、ゲーム的な理解を助ける表示として使う。

**BR-020 — Simple Wealth Story**  
富の説明は「どのくらい持っていたか」「何で稼いだか」「いつ増えたか」の三点へ絞る。

**BR-021 — Alpha Wealth Values**  
Alphaの資産額、内訳、推移はUI検証用の仮推定値とする。公開版の値は人物ごとに再調査する。

**BR-022 — Character Voice Bible**  
各人物にペルソナ、口癖、テンポ、比喩モチーフ、TTS速度、TTS高さを設定する。

**BR-023 — Copy Constraint**  
指定された禁止表現をアプリ内コピー、仕様書、コンテンツへ入れない。自動検査で検出する。

### 8.1 Provisional Location Defaults

以下は実装開始用の仮置きであり、現地テストで調整する。

- 通常の遭遇半径：150m
- GPS精度が良好とみなす目安：水平精度100m以内
- 手動チェックインを表示する目安：対象地点から300m以内、またはGPS精度が不十分な場合
- 正確な半径はスポットごとに設定可能にする
- 河川、道路、建物構造により誤判定しやすい地点は個別調整する

## 11. Error Handling

### 11.1 Location Permission Denied

- 図鑑、サンプル人物、購入画面は利用可能
- 周辺人物の自動表示は無効
- 位置情報が必要な理由と設定変更方法を表示
- 手動で現在地周辺スポットを選択できる導線を用意する

### 11.2 Approximate or Poor GPS

- 位置精度を画面上で責める表現をしない
- 遭遇判定半径を広げる
- 手動チェックインを表示する
- 何度も位置情報許可を要求しない

### 11.3 No Network

- インストール済みのCincinnatiパックを使用する
- 解説、音声、図鑑、写真は通常どおり利用可能
- 購入処理だけは通信が戻るまで実行できない
- 購入済み状態のローカルキャッシュがある場合は利用を継続する

### 11.4 Audio Playback Failure

- 全文テキストを表示する
- 再生ボタンを再試行可能にする
- 音声失敗によってアンロックを妨げない

### 11.5 Camera or Photo Permission Denied

- 「写真なし」で続行できる
- 人物アンロックを妨げない
- 後から写真を追加できる

### 11.6 Local Storage Full

- 写真保存だけ失敗させる
- 人物アンロックと進捗保存を優先する
- 写真を保存できなかったことを明示する
- 再試行または別写真選択を可能にする

### 11.7 Purchase Failure

- 有料人物をアンロックしない
- エラー内容を簡潔に表示する
- 再試行と購入復元を提供する
- 二重解放や重複購入状態を作らない

### 11.8 App Termination During Encounter

- 導入開始状態を保存する
- 再起動時に人物カードから再開できる
- 導入完了前であればアンロック済みにしない

### 11.9 Corrupt or Missing Asset

- 音声が欠損した場合はテキストへフォールバック
- キャラクター画像が欠損した場合は汎用シルエットを表示
- 一部アセットの失敗でアプリ全体をクラッシュさせない

### 11.10 Historical Error Report

- 対象人物、対象文章、アプリバージョンを報告へ含める
- 修正版コンテンツは次回ビルドで反映する
- V1ではリアルタイム更新を必須としない

## 13. Non-Functional Requirements

### 13.1 Usability

- 主要操作は片手で行える
- 1回の人物遭遇を長引かせない
- 導入は原則60〜90秒程度
- ユーザーを専用ルートへ拘束しない
- 地図より人物を主役として見せる
- 音声を使わなくても全機能を完了できる
- 質問を人物の台詞の直下へ置き、画面遷移を減らす
- 主要な資産情報は一目で理解できる
- デート中に相手へ見せやすい明るい画面と短い文章を使う

### 13.2 Performance

暫定目標：

- 起動後3秒以内にホーム画面を操作可能にする
- 人物カードのタップから1秒以内に導入画面を表示する
- 位置情報取得中もUIを操作可能にする
- 写真サムネイル表示でスクロールを阻害しない

### 13.3 Offline Availability

- Cincinnatiの主要体験は圏外で動作する
- 通信必須機能はsandbox購入と外部誤り報告に限定する
- オフライン状態をエラー画面として扱わない

### 13.4 Privacy

- 位置情報はアプリ使用中のみ
- バックグラウンド追跡なし
- ユーザーアカウントなし
- 写真クラウド送信なし
- 訪問履歴クラウド送信なし
- 写真ライブラリ全体の常時読み取りを要求しない
- 必要な権限と用途を事前説明する

### 13.5 Accessibility

- 音声には全文テキストを付ける
- Dynamic Typeへ対応する
- VoiceOverで主要操作を利用できるようにする
- キャラクター状態を色だけで区別しない
- 再生、一時停止、先送りを明確にする

### 13.6 Reliability

- 重複アンロックを防止する
- 一部アセット欠損で全体を停止しない
- アプリ中断後に主要進捗を復元する
- GPS誤差を理由にユーザーを行き詰まらせない

### 13.7 Content Quality

- 短く、具体的で、人間ドラマがある
- 年表の羅列を避ける
- 成功と負の側面を両方扱う
- 参照元を表示する
- 事実、伝承、演出を混同しない
- 人物ごとの口調を一読で区別できる
- 富の説明は短く、グラフと一言で理解できる

### 13.8 Cost

- V1では常時稼働するバックエンドを持たない
- 利用時の生成AIコストを発生させない
- 写真ストレージの継続費を発生させない
- コンテンツ生成費は制作時だけ発生する

## 17. Decisions Made

| ID | 決定 | 理由 |
|---|---|---|
| DEC-001 | コアを現実世界の歴史図鑑ゲームとする | 単なるAIガイドとの差別化と収集動機を作るため |
| DEC-002 | 主対象を20〜40代の個人旅行者とする | 歴史専門家と異なる旅行者の体験を深めるため |
| DEC-003 | 金・権力・成功を歴史の主軸にする | 人物ドラマとして強く、土地形成の因果関係を説明しやすいため |
| DEC-004 | 必要に応じて他の偉人や関係者も扱う | 富豪だけでは土地の歴史を正確に説明できないため |
| DEC-005 | 歴史人物をデフォルメキャラクターとして登場させる | 記憶、収集、親しみやすさを強化するため |
| DEC-006 | 旅行同行型にする | 専用ツアーへ拘束せず、通常の観光に追加価値を与えるため |
| DEC-007 | 近づいてタップし、導入を体験してアンロックする | 自動付与より発見感を残しつつ、操作負荷を抑えるため |
| DEC-008 | 一人称導入＋選択式質問にする | キャラクター性と内容制御を両立するため |
| DEC-009 | V1の質問と回答を事前制作する | 歴史的正確性、速度、オフライン性を確保するため |
| DEC-010 | 将来は固定回答＋AI自由質問へ拡張する | 深掘り需要へ対応する余地を残すため |
| DEC-011 | 音声＋全文テキストを提供する | 現地を見ながら聞く用途と、音を出せない用途の両方に対応するため |
| DEC-012 | 正式な共同利用機能は後回しにする | V1の実装範囲を抑えるため |
| DEC-013 | 最初の地域をCincinnatiにする | 現地検証を繰り返しやすいため |
| DEC-014 | Streetcar沿線を対象にする | 歴史密度、移動しやすさ、通常観光との相性がよいため |
| DEC-015 | 10〜12人物、20〜25スポットを収録する | 小さすぎず、V1制作量として制御可能な範囲にするため |
| DEC-016 | ホームは人物カード中心＋補助地図にする | 地図アプリ化を避け、人物を主役にするため |
| DEC-017 | 人物を主収集対象、場所・事件を関係ノードにする | キャラクター収集と歴史的因果関係を両立するため |
| DEC-018 | 選択写真を圧縮して端末内保存する | 写真記録を残しつつ、アカウントとクラウドを不要にするため |
| DEC-019 | 歴史コンテンツはAIで制作する | V1制作速度を優先するため |
| DEC-020 | AI生成物を固定コンテンツとして配布する | 利用時の誤生成、コスト、通信依存を避けるため |
| DEC-021 | 最初の3人を無料にする | 体験価値を理解してから購入判断できるようにするため |
| DEC-022 | Cincinnati完全版を$6.99買い切りにする | 1都市V1ではサブスクリプションの継続価値が弱いため |
| DEC-023 | GPS不良時は手動チェックインを許可する | 厳格な不正防止より、旅行中の失敗回避を優先するため |
| DEC-024 | バックグラウンド位置監視を行わない | バッテリー、権限、実装負荷を抑えるため |
| DEC-025 | オフライン利用可能にする | 旅行先の通信不良で主要体験を失わないため |
| DEC-026 | iOS先行とする | 最初の検証端末を絞るため |
| DEC-027 | TestFlightで自分と友人へ配布する | 一般公開前に現地体験を検証するため |
| DEC-028 | App Store一般公開をV1完成条件にしない | 市場公開よりプロトタイプ検証を優先するため |

# Appendix B. Character Content Template

各人物は最低限、以下を持つ。

## Identity

- 氏名
- 生没年
- 一言肩書き
- Cincinnatiとの関係
- 象徴物
- キャラクターシルエット
- デフォルメ立ち絵


## Voice Profile

- ペルソナ
- 口癖
- 文のテンポ
- 感情の強さ
- 職業由来の比喩モチーフ
- TTS速度
- TTS高さ
- 他人物と区別できる代表台詞

## Wealth Profile

- 推定資産・2026年ドル
- 資産戦闘力・0〜10,000
- ランク・S〜D
- 一言説明
- 富の由来・合計100%
- 年代別の資産推移
- Alpha仮推定ラベル

## Intro

- 一人称
- 60〜90秒
- 最初の一文でフックを作る
- 富、権力、事業、野心のどれかを含む
- 現在見えている場所との関係を含む
- 成功だけで終わらせず、代償または対立を示唆する

## Selectable Questions

例：

- どうやって金持ちになった？
- 最大のライバルは？
- この街に何を残した？
- 成功の代償は？
- 後世ではどう評価されている？

## Answers

- 事前制作
- 音声＋全文テキスト
- 1回答につき1つ以上の関係ノードを解放可能
- 根拠のない直接話法を避ける
- 演出した台詞は演出であることを明確にする

## Sources

- 参照資料
- 出版者
- 参照日
- 信頼度メモ
- 史実、伝承、演出の区分
